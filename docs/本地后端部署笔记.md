# 本地后端部署笔记

本文只记录通用部署要点，不包含任何真实地址、账号或密钥。

## 一、目录与挂载

容器化部署时，配置、数据、日志通常以 bind 挂载方式映射到宿主机。

| 宿主机路径 | 容器内路径 | 类型 |
|---|---|---|
| `.../server/config.json` | `/app/config.json` | 文件挂载 |
| `.../data` | `/app/data` | 目录挂载 |
| `.../logs` | `/app/logs` | 目录挂载 |

> 不要用 `docker cp` 指向 bind 挂载点内部。曾把宿主机的配置文件（文件挂载）替换成空目录，容器直接无法启动。正确做法是直接写宿主机挂载目录，或用 `docker exec -i ... cat > 路径`。

## 二、数据表

服务端启动时会读取大量 JSON 表（商店、抽卡、关卡、基建、危机合约、默认存档等）。

数据目录为空时不会报错，而是**静默降级**：接口照样返回 200，但内容为空。排查时极易误判成客户端问题。

## 三、账号

账号表通常包含 `uid / phone / password / secret / user` 等字段：

- `password` 多为 `md5(明文 + 固定盐)`；
- `secret` 是换取 token 的长期凭据；
- `user` 是完整存档；手写插入时若留空对象，玩家能登录但拿不到任何数据。

新建账号建议走注册接口，或复制一份完整存档，而不是手写 INSERT。

## 四、版本对齐

客户端登录时会上报版本，服务端比对配置中的版本号；不一致会返回「资源需要更新」。

资源的实际文件由客户端按版本号自行向 CDN 取；服务端只负责把路径映射过去。若开启了重定向，服务端返回 302；否则回源到本地后再转发（支持 `ETag` / `Range` / `304`）。

> 版本号既用于登录校验，也直接拼进 CDN 路径，两处必须一致，否则会出现「登录通过但资源 404」。

## 五、升级与回滚

```bash
# 备份
docker cp <container>:/app/server.jar ./server.jar.bak
# 替换（写容器内文件，不碰挂载点）
cat new.jar | docker exec -i <container> sh -c 'cat > /app/server.jar.new'
docker exec <container> sh -c 'mv /app/server.jar.new /app/server.jar'
# 重启并验证
docker restart <container>
```

## 六、故障处置

| 现象 | 排查 |
|---|---|
| 容器起不来，报 mount 不是目录 | 挂载源类型被破坏，检查对应路径是文件还是目录 |
| 接口 200 但内容为空 | 数据目录缺表 |
| 登录返回「资源需要更新」 | 版本号与客户端不一致 |
| 登录后没有干员 / 资源 | 该账号存档为空 |

## 七、已知问题：写死的回环地址

部分协议链接在服务端写死为 `127.0.0.1`，客户端在设备上运行时该地址指向设备自身。

实测正常流程不会请求这些链接，只有用户点开协议超链接时才会失败，属于潜在隐患而非阻塞项。处理方式：设备侧端口转发、客户端改写响应体，或服务端改为可配置（需重新打包）。
